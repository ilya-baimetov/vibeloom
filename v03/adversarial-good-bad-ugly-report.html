§1 · Executive Verdict

Most intellectually serious entry in the wave. And the hardest to adopt.

VibeLoom diagnoses the right problem — intent debt compounds as context fragments — and is structurally ahead of Kiro / Spec Kit / BMAD / Tessl, all of which are per-feature or per-file and go stale by construction. The graph-backed contract, verification ladder, dispatch waves, and trace substrate are the only whole-system governance sketch in the landscape.

The inverse is also true: a prospect must learn 41 templates, 43 prefixes, 5 modes and 6 status categories before the governance pays back — and payback only arrives after the second or third generation cycle. Without a 90-second visceral demo of that payback, distribution never starts. The runnable substrate (v02) is materially behind its own spec (v03).

◆ One reason to say YES

Lifecycle governance is correct. Graph-backed staleness, patch-staged validation, dispatch waves and the trace-derived learning substrate are the only attempt at whole-system coherence across regeneration. The verification ladder is honest about what is decidable today vs heuristic. If AI-generated systems must survive 3+ cycles with 2+ contributors, this architecture is the right shape.

▣ One reason to say NO

No one has asked for it yet — and nobody will stumble into it. Zero validated demand signals (waitlist, LOI, stars, pilots) in deck or repo. Onboarding tax guarantees the prospect bounces before the lifecycle benefit appears. Distribution is unspecified and the skill is forkable in ~200 LOC. Solo-founder thesis risk at a founder-bet program.

§3 · Bad — Friction and half-built promises

Twelve issues that make adoption heavier than the code it governs.

Each is shippable-but-painful. Together they define where the next eng-month should go — not in more spec.

B1 · Ceremony tax heavier than the system · taxonomy 100+ tokens
41 templates (4365 lines), 43 prefixes, 6 tiers, 5 modes, 6 statuses, 6 trace families, 14 tasks. New adopter must hold the taxonomy before shipping. "30-minute on-ramp" (getting-started.md:1–8) branches to 5 examples + comparison + roadmap and never narrows; honest guidance budgets "half-day to day for import on 50K-LOC" (getting-started.md:82–86).
CANON-01 deferred to v04ideas.md ≈ roadmap 80% overlap
B2 · v03 spec-only — runnable is v02 behind it
README banner "Spec-only — engine catches up in v0.3.x". v03/engine/ ~20 modules +17 tests exists but v02 is the runnable 0.2.0 (no ux-specs, no state/, snapshot vs trace, hosted_bounded_contexts vs singular). getting-started.md:14–18 points the agent at v03/ — the first command hits the seam.
B3 · Authority still split across three homes
Tech Stack per-layer shape normatively in methodology §6.1 + implementation §6 + defaults.md. Review loop in 4 places (review-canon/site/skill + tasks/review.md). Only the §6.1 code block was mitigated; CANON-01 deep refactor deferred (fix-pass Residual #1) + SKILL-09 loop consolidation deferred (roadmap E6 calls it "edit all four consistently").
B4 · 43 prefixes + 1:1 BC→component over-engineer the domain
Methodology §6.5 1:1 mapping ("each domain component hosts exactly one BC") turns a modeling decision into a blocking eval finding (eval_.py:_layered_invariants). Table entries like FR ← (CAP,OBJ,STORY) / VIEW ← (CAP,STORY,FLOW) are prose judgment no adopter will memorize. Governance becomes taxonomy past FR/STORY/BC.
B5 · Code-sync is shallow — claims, not guarantees
Trace connects [CMP,IF,BEH,VIEW] → owned_paths + file_hashes + validation{typecheck,unit} (impl §8.2). Honest caveat: "no deep function-level carriers". A subagent can claim realizes:[CMP-0012] with plausible hashes; no structural check proves line 42 realizes BEH-0031. "Dark factory — humans never inspect code" rests on an unverified claim.
B6 · Verification ladder trajectory is faith-based
eval_.py:_coverage → {} and _required_downstream → {} (TODO "kept simple in v0.3"). Six statuses double-cover the same ground (stale hash mismatch, dangling retired, uncovered never-approved, drifted hash OR finding OR direct-edit). Seeing drifted without reason gives no fix signal. A4 instrumentation is roadmap-deferred.
B7 · Brownfield import confidence is uncalibrated
Single-task scoping subagent emits confidence ∈ [0,1] + evidence_refs + uncertainty into imports.jsonl:per_candidate (impl §15.8). Score is LLM self-report, never calibrated; richest outputs (BC cohesion, AGG boundaries) are where LLMs hallucinate. Approving a 0.81 on "cohesion ambiguous; could be split" (impl §8.6 example) at face value bakes a wrong domain model into the contract.
B8 · Status and staleness are two similar machines
status.py:classify_items and staleness.py:compute_staleness both compute latest_approval_per_item + current-hash and emit overlapping taxonomies. Existence of sibling staleness CLI beside status invites "which do I run?" confusion about recommended-next.
B9 · Decision dual-ID, specified coarsely
trace_id: DEC-YYYYMMDD-NNNN + record_id: ADR/PDR/UDR/IDR-NNNN (absent for general) codified via CANON-03, but traces.py:REQUIRED_FIELDS["decision"] = (topic,payload) doesn't enforce co-presence; prose examples still carry older dated ADR-YYYYMMDD forms. Tri-state (dated trace / sequence record / null) is easy to mishandle.
B10 · Comparison sharp on the page, softer in disclosure
research/sdd-landscape.md disclosure ("not yet field-validated", aspirational-marked) is admirable; site/public/methodology.html FAQ still ships blunt "Spec Kit, Kiro, BMAD keep humans on the factory floor … VibeLoom is the only one" without per-claim sourcing or aging. Prior SITE-04 flagged; JSON-LD softened, page FAQ stayed sharp.
B11 · Getting-started funnels nowhere
30-min on-ramp branches to manifesto → methodology → implementation → 5 examples → comparison → roadmap. v03 canon is ~15k lines; file-layout.md adds v04+ layout on top. Two orthogonal skills (v03/skill vs vibeloom-dev) double the first-hour cliff despite the README callout.
B12 · Vibe "private scaffolding" specified by absence
Methodology §5.1 + impl §2.2/§15.6: vibe's cache/code-sync-like evidence is "private runtime data, not canon". No invariant defines how private: gitignored? readable by status? usable for upgrade? Permission "engine may create" is not a rule — either extreme (nothing vs full graph) claims compliance with different quality.
§4 · Ugly — Existential risks

Seven bets that, if wrong, make the other 90% irrelevant.

▣ How to read this section

Ugly ≠ "bad code". Ugly = structural bet. Flip any one and the methodology is not locally fixable — it needs a different go-to-market or a different governance shape.

U1 · No validated demand — pre-customer artifact
Pitch slide: 4 docs, 17 citations, v0.3 impl, 5 modes, brownfield import — zero numbers about anyone outside the founder engaging. Disclosure in research/sdd-landscape.md "not yet field-validated at this scale" appears twice. SDD tooling is a credence good (cannot be evaluated without living with it for a month); distribution requires owned audience (Cursor/Kiro) or flywheel (Spec Kit 83k stars). VibeLoom has neither; skill is forkable in ~200 LOC (Adversarial-Review-EWOR.md:E2).
U2 · Solo-founder thesis risk — one architect, no complement
Founder on slide 11 of 12 at a 99% founder-bet program; "solo. on purpose." reads as defensive rationalization. Repo velocity (v01→v03 + 4365-line template spec in ~4 weeks) signals writing capacity, not shipping cadence. No GTM / community operator / second pair of eyes on semantic eval quality. The approve→generate→status loop assumes a PM/dev/design counterparty that does not exist yet.
U3 · Core value is LLM-heuristic with deterministic wrapping
Defensibility is presented as deterministic (graph, staleness, waves, traces). Value lives in semantic eval: faithful repr., naming, capability gaps, UX/product mismatch, mockup extraction. Today _coverage → {}, _required_downstream → {}. The hard question — are these the right bounded contexts? — has no decidable form. System governs what is cheap (field presence, cycles) and asks the human to govern what is expensive — the cognitive load it promised to reduce.
U4 · Engine state loss is fatal and unrecoverable
vibeloom-implementation.md:§3.3 "State loss is fatal in v03 — there is no recovery procedure." .vibeloom/traces/ durable append-only, .vibeloom/state/id-registry.json durable mutable, .vibeloom/cache/ regenerable — but io_.py exposes traces_dir/cache_dir/runs_dir and not state_dir; registry.py:registry_path still resolves via traces_dir despite the spec move. One rm -rf .vibeloom/cache accident away; no guard distinguishes fatal from safe deletion.
U5 · Contract bloat is the new intent debt
Manifesto §5 anchor: "108K-LOC governed by contract ~24% of code volume (Vasilopoulos 2026)" — one project. A4 instrumentation is roadmap-deferred, so bloat is invisible. Trend is upward: ideas.md:§4 proposes SLICE/DELTA/CMAP plus compliance / CGKG-B, each adding prefixes + templates. No proposal declares "adds N templates, weekly review minutes, deprecation offset." Easiest thing to add in a solo spec — more contract — is exactly the debt the paradigm prevents.
U6 · Distribution unspecified; the moat is prose
ideas.md:B1 pattern library flagged "alternative templates→implementation idea may differ"; roadmap says registry could be "central or org-private" and "natural moat". No GTM funnel, channel, named top-50 targets, or burn/runway math beyond a 60/25/15 pie (Adversarial-Review-EWOR.md:A1/F/E1). If Spec Kit's constitution is free and durable, VibeLoom must demonstrate weekly payback that justifies weekly review cost — prose does not.
U7 · Mode coherence unchecked across the lifecycle
v02/SKILL.md [vibe|pm|dev|expert] vs v03 [vibe|pm|dev|ux|expert]; file-layout.md:§4 vibeloom-dev targets without ux; models.py:ArtifactType pre-ux; status.py:_infer_mode infers from ux.md presence and fails for expert-without-ux. Mode is the user's first decision (/vibeloom init --mode) and it drifts per artifact.

◆ Meta-finding — the pattern behind the regressions

Walk 2 introduced 5 findings after Walk 1's fixes — 3 were propagation gaps (a fix edited methodology or implementation without touching every consumer) and 2 were reviewer-introduced false claims. The fix is not "review harder"; it is extract-references.py --check and a schema linter that fails CI when consumers drift.

§6 · Actionable Recommendations — 14 operations with gates

No more spec until there is a demo and a demand signal.

Prioritized by founder time to first external validation. Each is a narrow operation with a defined artifact and a gate — not a prose edit.

R6 · Make the 30-minute on-ramp measurable
Action: checkpoint vibe: init→approve→generate→status ≤25 min on a clean machine. One-command smoke: check_site.py + extract-templates.py --check + pytest -q. If vibe cannot be timed, ship claim as "~1 hour" instead of "30 minutes".
R7 · Single-source the authority split
CANON-01 + SKILL-12 residue. Action: generate skill/references/artifacts.md + eval.md schema tables from implementation §5.1/§8 via extractor (extract-references.py --check in CI). R8 · Shell guard for state vs cache
U4 — fatal vs safe deletion. Action: cli.py:_resolve_repo warns if id-registry.json not in .vibeloom/state/; pre-commit guard refuses git clean -xfd patterns dropping state/ without vibeloom export-state. Document state/+traces/ backup in getting-started.md.
R9 · Calibrate or remove import confidence
B7 — numeric confidence ∈ [0,1] is uncalibrated. Action: either replace with {high,medium,low} + uncertainty only, or ship a 20-case calibration set (hand-labeled BC/CMP/FR vs inferred, scored precision/recall) gating numeric form. Until calibrated, never surface 0.81 in a review packet.

Action: DM 200 senior eng/CTOs with manifesto + one question ("most expensive drift shipped last 6 months?"), count replies, book 15 × 30-min calls, map each to mode (vibe/pm/dev/ux). Publish the null result too: "47 DMs → 12 replies → 4 calls → 1 pilot" is signal; "47→2" is market signal. Put top two counts on slide 10; link raw sheet. B2 moves Low → Medium.
R11 · Instrument cognitive-surface on VibeLoom itself
A4 is roadmap-deferred. Action: add to status.py: contract_items_reviewed, code_items_generated, compression_ratio, review_minutes_per_packet, rework_per_approval. Report after every generate/review/reconcile cycle on VibeLoom itself. Publish 5-cycle trend in site/public/index.html. Manifesto "24% of volume" anecdote → live metric.
R12 · Commit to a mode taxonomy experiment
B4 + U7. Action: 3 pilots on different modes (solo vibe, PM-led, designer-led ux). After 2 weeks: did the gate map match rhythm or get rubber-stamped? If ux has zero pilots, cut to 3 modes (vibe/pm/expert) — fewer modes, clearer message, ~15% less template branching.

Heal "humans never touch construction site" → "humans never edit code directly in governed scopes; patches staged, validated, then applied."
